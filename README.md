# 北海道、旅のまとまりを探して。

30DayMapChallenge 2026 Day4「Clusters」の作品。北海道の観光資源を地理的な距離でグループ化し、短い操作ガイドと自由な操作で「まとまり」を探す静的 Web アプリ。

中心メッセージは「クラスターにすると見えてくる」。個々の観光地を探すアプリではなく、複数の資源をまとめたときに現れる広がり・種別の構成・行政界を越えた集積と、その分裂・合流を読む。

> 北海道では、観光客の地域偏在や、二次交通による周遊のしづらさが課題とされています。この地図では2014年版の観光資源データを距離でグループ化し、行政界を越えた「一緒に巡る候補」を探ります。まとまりは代表位置間の距離に基づくもので、実際の交通アクセスや周遊実績を示すものではありません。

### 初期調査の結果

`npm run data:build` の出力（`public/data/manifest.json` の `stats`）より。

- 点レコード総数 **35**、有効座標 35、除外 0
- ID（P12_001）重複 0、完全に同じ座標の重複 0（最も近い 2 点は約 50m 以内：大通公園とさっぽろ雪まつり）
- 欠損：P12_007（観光資源分類コード）が **35 件すべて -1（未設定）**。その他の属性に欠損なし
- 座標範囲：経度 140.686〜145.332、緯度 41.759〜45.290
- 文字コード Shift_JIS（CP932）。`.prj` と GML は JGD2000、配布ページの表記は JGD2011（いずれも地理座標）
- 線 `P12b`（3 件）と面 `P12c`（15 件）は、すべて点レイヤにも同じ ID で存在する。代表点化して足すと二重計数になるため使わない

北海道ファイルは観光資源台帳（日本交通公社）A級以上などを元にしたデータで、件数は 35 と少ない。北海道の全観光スポットを網羅するものではなく、現在の営業や入場可否も示さない。

### 種別とカテゴリ

| 大分類 | 種別（P12_005）と件数 |
| --- | --- |
| 自然資源 24 | 山岳 6、高原・湿原・原野 4、湖沼 7、河川・峡谷 3、海岸・岬 1、動物 1、植物 1、自然現象 1 |
| 人文資源 11 | 城跡・城郭・宮殿 1、集落・街 1、郷土景観 2、庭園・公園 2、年中行事 1、動植物園・水族館 1、温泉 1、食 2 |

- 公式の観光資源分類コード（P12_007：自然／歴史・文化／温泉・健康…）は北海道分が全件未設定のため、分類には使えない
- フィルタは原分類の種別名称（P12_005）で行う。「自然資源／人文資源」の大分類は、観光資源台帳の区分に合わせた対応表（`public/data/categories.json`）による。未分類が出た場合は「未分類」として表示する

### 座標変換

元データの地理座標（JGD2000/JGD2011）を EPSG:4326 として扱い、小数第 7 位で丸めた。測地系の差は本作品の距離判定（km 単位）と元データの位置正確度（図上 0.3mm 以内）に比べて無視できる。点は施設入口ではなく、資源の中心部などの代表位置。

### 配信ファイル（`public/data/`）

- `resources.geojson`：観光資源点（ID 昇順、自治体コードと 2014 年時点の自治体名を同じレコードから対応付け）
- `categories.json`：種別キー・大分類の対応表
- `manifest.json`：取得元 URL・取得日・基準日・CRS・件数・除外理由・変換方法・利用条件

## クラスタリング

- アルゴリズムは DBSCAN（`src/lib/dbscan.ts`、依存ライブラリなし）
- 距離は Haversine 式による地表距離（km、地球半径 6371.0088km）。近傍は「距離 ≤ ε」
- minPts は**本人を含めて**数える
- 入力 ID を昇順に並べて探索するため、同じデータ・条件なら同じ結果になる。境界点は昇順探索で最初に到達したクラスタに入る
- 全点間距離は起動時に 1 回だけ計算して行列にキャッシュ（35 点なので空間索引や Web Worker は不要と判断）
- 距離の変更は 90ms のデバウンスと最新要求 ID で処理し、古い結果で画面を上書きしない
- 輪郭は分類後に描く凸包（Web メルカトル上で計算）。2 点・一直線上は線、同じ位置だけの群は輪郭なし。海・山・非メンバーを含むことがあり、内側すべてを巡れる意味ではない
- 色は前回とのメンバーの重なりで引き継ぐ（分裂は最大の子、合流は最大の寄与元）。初期表示・共有 URL ではメンバー由来の安定色。色は識別の補助で、同一性は保証しない

### 採用した初期値

`npm run data:scan` で 5〜150km、minPts 2〜4 を計算して選んだ（抜粋、minPts=3）。

| ε (km) | まとまり | 孤立点 | 様子 |
| --- | --- | --- | --- |
| 20 | 2 | 26 | 札幌中心部・函館市街だけがまとまる |
| 30 | 5 | 14 | 旭川周辺、登別・洞爺、阿寒・摩周が現れる |
| **40** | **6** | **7** | 札幌・函館・大雪・阿寒/摩周・利尻/天塩・登別/洞爺に分かれる |
| 60 | 4 | 1 | 札幌〜登別〜函館が連鎖で合流、道東 9 地点がひとつに |
| 100 | 2 | 0 | ほぼ全体が 1 つ |
| 120 | 1 | 0 | 全 35 地点が 1 つ |

- 初期値：**ε = 40km、minPts = 3**。初期表示から 6 つのまとまりが読め、60km 前後への変化で合流が見える
- スライダー範囲：1〜120km（120km で全点が 1 群になるため上限）。minPts は 2〜10
- 計算時間（実測）：35 点の DBSCAN 1 回あたり平均 0.054ms（Node v22.23.4、開発用コンテナで 500 回の平均）。ブラウザ端末での操作応答は未計測

## 画面

- 地図 1 画面。PC は地図＋右の操作パネル、スマホは地図＋下部シート
- 3 ステップのガイド（まとまりを読む／距離で変化を見る／テーマで比較する）。該当操作のそばに表示し、戻る・次へ・スキップ・再表示が可能。ガイドの開閉で設定・選択・地図位置は変わらない
- 「まとまり／点だけ」の比較切り替え（初期はまとまり）
- 選択カード：地点数・自然/人文の構成・種別・最大直線距離・含まれる自治体・名称一覧。孤立点は最も近い対象地点までの距離を表示
- テーマ変更で選択中の地点が対象外になった場合や、まとまりが孤立点になった場合は通知する
- 近い点が重なる場所をクリックすると候補一覧から選べる
- 設定 URL のコピー、PNG 保存（任意の特集タイトル、凡例・出典・基準日入り）。背景タイルを取り出せない場合は背景を省いた出典付き画像に切り替える
- キーボード操作、スライダーの数値入力、色以外の選択強調（破線・太枠）、孤立点は白抜き、`prefers-reduced-motion` 対応

### URL パラメータ

| キー | 内容 |
| --- | --- |
| `v` | schema 版（`1`）。違う場合はすべて初期値 |
| `d` | 近所とみなす距離（1〜120） |
| `m` | 何地点から集まり（2〜10） |
| `c` | `all` / `nature` / `culture` / 種別キーを `.` で連結 / `none` |
| `s` | 選択した観光資源 ID（まとまりはこの資源を含む群として復元） |
| `view` | `points` で点だけ表示 |
| `map` | `経度,緯度,ズーム` |
| `t` | 特集タイトル（40 字まで、テキストとして表示） |

不正な値はその項目だけ初期値に戻す。

## 開発

Node.js 22.18 以上（データスクリプトが型除去で TypeScript を読み込むため）と `unzip` コマンドが必要。

```bash
npm ci
```

```bash
npm run data:fetch   # 北海道 ZIP を data/raw/ に取得・展開（data/raw は git 管理外）
```

```bash
npm run data:build   # public/data/ の GeoJSON・カテゴリ表・manifest を生成
```

```bash
npm run data:scan    # 距離・minPts ごとの結果と計算時間を表示
```

```bash
npm run dev
```

```bash
npm test && npm run build   # 検証とビルド（dist/ に出力）
```

`dist/` は相対パスで出力するので、GitHub Pages などの静的ホスティングにそのまま置ける。公開先は未定。

### 構成

- Vite 7.3.7 ＋ React 19.2.9 ＋ TypeScript 5.9.3 ＋ MapLibre GL JS 5.24.0（依存バージョンは固定）
- 背景地図：地理院タイル（淡色地図）。API キー・常駐サーバー・実行時 AI は不要
- `src/lib/`：距離・DBSCAN・凸包・配色の計算モジュール
- `tests/`：計算（距離境界・孤立点・同位置点・連鎖・minPts・カテゴリ変更後の再計算・再現性・色の引き継ぎ）、URL、配信データ件数の検証
