# Shabon Hokkaido — How Near Is Near?

北海道の観光地を、距離でまとめる地図。

30DayMapChallenge 2026 Day4「Clusters」の作品。北海道の観光資源を地理的な距離でグループ化し、短い操作ガイドと自由な操作で「まとまり」を探す静的 Web アプリ。

問いは「How Near Is Near?（どこまでが近所？）」。近所とみなす距離を変えると、観光のまとまりがしゃぼん玉のようにくっついたり分かれたりする。個々の観光地を探すアプリではなく、複数の資源をまとめたときに現れる広がり・種別の構成・行政界を越えた集積と、その分裂・合流を読む。

> 北海道では、観光客の地域偏在や、二次交通による周遊のしづらさが課題とされています。この地図では2014年版の観光資源データを距離でグループ化し、行政界を越えた「一緒に巡る候補」を探ります。まとまりは代表位置間の距離に基づくもので、実際の交通アクセスや周遊実績を示すものではありません。

### 初期調査の結果

`npm run data:build` の出力（`public/data/manifest.json` の `stats`）より。

- 点レコード総数 **35**、有効座標 35、除外 0
- ID（P12_001）重複 0、完全に同じ座標の重複 0（最も近い 2 点は約 50m 以内：大通公園とさっぽろ雪まつり）
- 欠損：P12_007（観光資源分類コード）が **35 件すべて -1（未設定）**。その他の属性に欠損なし
- 座標範囲：経度 140.686〜145.332、緯度 41.759〜45.290
- 文字コード Shift_JIS（CP932）。`.prj` と GML は JGD2000、配布ページの表記は JGD2011（いずれも地理座標）
- 線 `P12b`（3 件）と面 `P12c`（15 件）は、すべて点レイヤにも同じ ID で存在する。代表点化して足すと二重計数になるため使わない

北海道ファイルは観光資源台帳（日本交通公社）A級以上などを元にしたデータで、件数は 35 と少ない。北海道の全観光スポットを網羅するものではなく、現在の営業や入場可否も示さない。

- 公式の観光資源分類コード（P12_007：自然／歴史・文化／温泉・健康…）は北海道分が全件未設定のため、分類には使えない
- フィルタは原分類の種別名称（P12_005）で行う。「自然資源／人文資源」の大分類は、観光資源台帳の区分に合わせた対応表（`public/data/categories.json`）による。未分類が出た場合は「未分類」として表示する

### 座標変換

元データの地理座標（JGD2000/JGD2011）を EPSG:4326 として扱い、小数第 7 位で丸めた。測地系の差は本作品の距離判定（km 単位）と元データの位置正確度（図上 0.3mm 以内）に比べて無視できる。点は施設入口ではなく、資源の中心部などの代表位置。

### 参考レイヤ：道の駅

国土数値情報「道の駅」平成30年（P35-18、非商用）から北海道分 **122 件**（全国 1,145 件）を `public/data/michinoeki.geojson` に抽出。ひし形で重ね、ホバーで名称と市町村を表示する。まとまりの計算には含めない。道路（高速・国道・道道など）とあわせて、パネルの凡例から表示を切り替えられる（URL `ov`）。

### 参考レイヤ：鉄道

国土数値情報「鉄道時系列データ」2025年度版（N05-25、**非商用**、2025年末時点）を、#30DayMapChallenge 2026 Day1「[駅のあった北海道](https://github.com/shinyanakashima/30daymapchallenge-2026day1-station-history)」で北海道向けに加工したデータを、コミットを固定して取得する（`scripts/build-rail.mjs`）。

- `rail.geojson`：2025年末時点で営業中の路線（32 区間）。昼は濃い線に白い破線、夜は淡く光る線
- `rail-history.geojson`：1950年以降に営業していた区間（213 区間、重複除く）。「廃止された路線」で破線を重ねる（初期は非表示）
- `stations.geojson`：2025年末時点で営業中の駅（422 駅）。ズーム 7 以上で表示し、ホバーで路線・事業者を表示
- 線は Douglas–Peucker（許容 約20m）で間引いた。まとまりの計算には含めない
- CC BY の N02「鉄道データ」とは別製品で、利用条件が異なる

### 参考レイヤ：空港

国土数値情報「空港」令和3年（C28-21、**商用可**、基準日 2021年12月31日）から、行政区域コードが北海道（01）の空港を標点位置の点にした（`public/data/airports.geojson`、13 件。うち礼文空港は休止中）。供用中の空港をゆっくり明滅する光で示し、休止中は白抜き。`prefers-reduced-motion` では明滅しない。まとまりの計算には含めない。

### 配信ファイル（`public/data/`）

- `resources.geojson`：観光資源点（ID 昇順、自治体コードと 2014 年時点の自治体名を同じレコードから対応付け）
- `categories.json`：種別キー・大分類の対応表
- `manifest.json`：取得元 URL・取得日・基準日・CRS・件数・除外理由・変換方法・利用条件（道の駅は `overlays.michinoeki`）
- `michinoeki.geojson`：道の駅（参考レイヤ）

### 比較用：2010年度版（第2.0版）

パネルの「観光資源データの版」で、国土数値情報「観光資源」第2.0版（P12-10、2010年度作成、非商用）に切り替えられる（URL `ed=2010`）。2014年版の35地点では点が少なく、まとまりの見え方を密度で比べるための**比較用の古い版**として扱う。

- 全国 2,019 レコードから行政区域コードが北海道（01）のもの **144 件**を抽出し、**141 件**を使用（`npm run data:build` → `public/data/manifest-2010.json`）
- 除外 3 件（五色ヶ原・駒ヶ岳・大沼）：北海道の行政区域コードなのに座標が本州にあるレコード。同名の本州の資源の座標と見られ、北海道側の座標を持つ同じ名称・コードのレコードが別にある
- 観光資源 ID・住所の列がないため、ID は（行政区域コード, 名称, 経度, 緯度）順に 20001 から付番。自治体名は国土数値情報の行政区域コード表（令和6年1月1日現在、廃止コードを含む）から引いた。複数の自治体にまたがる資源はすべて列挙
- 種別は第2.0版の原文（山岳19、湖沼22、植物18、岬9 など24種別）。自然資源 116／人文資源 25
- 第2.2版とは収録基準・種別名が異なり、件数をそのまま比べられない
- 距離の初期値は 25km（下表）。版を切り替えたときは、比較しやすいよう距離・最小地点数を保つ

| 20 | 13 | 47 |
| **25** | **16** | **31** |

## クラスタリング

- アルゴリズムは DBSCAN（`src/lib/dbscan.ts`、依存ライブラリなし）
- 距離は Haversine 式による地表距離（km、地球半径 6371.0088km）。近傍は「距離 ≤ ε」
- minPts は**本人を含めて**数える
- 入力 ID を昇順に並べて探索するため、同じデータ・条件なら同じ結果になる。境界点は昇順探索で最初に到達したクラスタに入る
- 全点間距離は起動時に 1 回だけ計算して行列にキャッシュ（35 点なので空間索引や Web Worker は不要と判断）
- 距離の変更は 90ms のデバウンスと最新要求 ID で処理し、古い結果で画面を上書きしない
- まとまりは「にじみ」で表す。分類後、各メンバー点のまわりに半径 ε/2 のにじみを MapLibre の heatmap レイヤ（色ごとに 1 枚）で描き、濃度の閾値付近で縁をぼかして塗る（輪郭線は描かない）。2 点のにじみはおおむね距離 ε 以内で重なるので、見た目のつながりが「近所」の意味と対応する。孤立点にはにじみを付けない。海・山にかかることがあり、範囲内すべてを巡れる意味ではない（`src/blob.ts`）
- 色は前回とのメンバーの重なりで引き継ぐ（分裂は最大の子、合流は最大の寄与元）。初期表示・共有 URL ではメンバー由来の安定色。色は識別の補助で、同一性は保証しない

### 採用した初期値

`npm run data:scan` で 5〜150km、minPts 2〜4 を計算して選んだ（抜粋、minPts=3）。

| ε (km) | まとまり | 孤立点 | 様子 |
| --- | --- | --- | --- |
| 20 | 2 | 26 | 札幌中心部・函館市街だけがまとまる |
| 30 | 5 | 14 | 旭川周辺、登別・洞爺、阿寒・摩周が現れる |
| **40** | **6** | **7** | 札幌・函館・大雪・阿寒/摩周・利尻/天塩・登別/洞爺に分かれる |
| 60 | 4 | 1 | 札幌〜登別〜函館が連鎖で合流、道東 9 地点がひとつに |
| 100 | 2 | 0 | ほぼ全体が 1 つ |
| 120 | 1 | 0 | 全 35 地点が 1 つ |

- 初期値：**ε = 40km、minPts = 3**。初期表示から 6 つのまとまりが読め、60km 前後への変化で合流が見える
- スライダー範囲：1〜120km（120km で全点が 1 群になるため上限）。minPts は 2〜10
- 計算時間（実測）：35 点の DBSCAN 1 回あたり平均 0.054ms（Node v22.23.4、開発用コンテナで 500 回の平均）。ブラウザ端末での操作応答は未計測

## 画面

- 白いページに、角丸と大きな影で浮かせた地図カード 1 枚。操作の UI はすべて地図の上に重ね、普段は小さな札と操作バーだけを見せる
  - 左上：タイトルと操作ガイド（?）
  - 右上：件数の札（対象地点・まとまり・孤立点）。押すとまとまりの一覧と凡例が開く。まとまりや地点を選ぶと、その下に詳細カードが浮かぶ
  - 下中央：操作バー（まとまり／点だけ、近所とみなす距離のスライダー、何地点から集まり、テーマ、レイヤ、その他）。各窓は押したボタンの上に開き、Esc で閉じる
  - 距離のスライダーは操作バーの主役として大きく置く。数値は大きく表示し、変えるとカウントアップ／ダウンする。値を上げるとつまみからしゃぼん玉が昇り、下げると小さく出てはじける。数値を押すと直接入力できる。`prefers-reduced-motion` ではカウントもしゃぼん玉も止める
  - 「レイヤ」：鉄道・廃止された路線・空港・道の駅・道路の表示と、背景地図の昼／夜
  - 「…」：観光資源データの版、地点の追加（GeoJSON）、設定 URL のコピー、PNG 保存、この地図とデータについて（説明・出典・計算方法）、初期設定に戻す
- スマホでは地図カードを画面いっぱいにし、操作バーを 2 段（距離／その他の操作）にする。詳細カードは操作バーの上に出す
- 3 ステップのガイド（まとまりを読む／距離で変化を見る／テーマで比較する）は、件数の札・距離スライダー・テーマのボタンを指す吹き出しで出す。戻る・次へ・スキップ・再表示が可能で、開閉しても設定・選択・地図位置は変わらない
- 地点にホバーすると名称・種別・所在地・所属するまとまりを表示。クリック（タップ）でポップアップを残し、詳細カードを開く
- 選択カード：地点数・自然/人文の構成・種別・最大直線距離・含まれる自治体・名称一覧。孤立点は最も近い対象地点までの距離を表示
- テーマ変更で選択中の地点が対象外になった場合や、まとまりが孤立点になった場合は通知する
- 近い点が重なる場所をクリックすると候補一覧から選べる
- GeoJSON（点）の読み込み：利用者が好きな地点を追加できる。ファイルは送信せずブラウザ内で処理し、このブラウザに保存する。名称は `name`／`名称`、種別は `kind`／`category`／`種別` などから読み取る。テーマ「すべて」で元データと合算、「追加データ」で追加分だけをまとめる。上限 2,000 地点・10MB。線・面は使わない。追加データは共有 URL に含まれず、PNG には件数を明記する
- PNG 保存（任意の特集タイトル、凡例・出典・基準日入り）。背景地図を取り出せない場合は背景を省いた出典付き画像に切り替える
- キーボード操作、スライダーの数値入力、色以外の選択強調（にじみを濃く・メンバー点を濃い縁取り・一覧は太枠）、孤立点は白抜き、`prefers-reduced-motion` 対応
- 背景は「衛星写真」（既定）と「夜の地形」を切り替えられる（URL `bm=night`）
  - 衛星写真：縮小〜中縮尺は Sentinel-2 cloudless 2016（EOX、CC BY 4.0）、ズーム約12以上は地理院タイル（全国最新写真（シームレス））。地理院の写真は縮小時の世界衛星モザイクにデータのない灰色の帯があるため、拡大時だけ使う
  - 夜の地形：Terrain Tiles（Mapzen ほか、AWS Open Data）の陰影と陸海の色分け
  - 海岸線・道路・地名は地理院ベクトルタイル（最適化ベクトルタイル）。いずれも CORS 対応で PNG 保存に入る。API キー・常駐サーバー・実行時 AI は不要

### URL パラメータ

| キー | 内容 |
| --- | --- |
| `v` | schema 版（`1`）。違う場合はすべて初期値 |
| `d` | 近所とみなす距離（1〜120）。省略時は版ごとの初期値 |
| `m` | 何地点から集まり（2〜10） |
| `c` | `all` / `nature` / `culture` / `user`（追加データ）/ 種別キーを `.` で連結 / `none` |
| `s` | 選択した観光資源 ID（まとまりはこの資源を含む群として復元） |
| `view` | `points` で点だけ表示 |
| `map` | `経度,緯度,ズーム` |
| `t` | 特集タイトル（40 字まで、テキストとして表示） |
| `ed` | `2010` で比較用の2010年度版。省略時は2014年版 |
| `bm` | `night` で夜の背景地図。省略時は昼 |
| `ov` | 参考レイヤ：`r`（道路）・`e`（道の駅）・`a`（空港）・`t`（鉄道）・`h`（廃止された路線）の組み合わせ、`none`。省略時は廃止された路線以外を表示 |

不正な値はその項目だけ初期値に戻す。

## 開発

Node.js 22.18 以上（データスクリプトが型除去で TypeScript を読み込むため）と `unzip` コマンドが必要。

```bash
npm ci
```

```bash
npm run data:fetch   # 観光資源（2014年版北海道・2010年版全国）・道の駅・空港の ZIP と行政区域コード表を data/raw/ に取得・展開（data/raw は git 管理外）
```

```bash
npm run data:build   # public/data/ の GeoJSON・カテゴリ表・manifest・道の駅・空港・鉄道を生成（鉄道は Day1 リポジトリから取得）
```

```bash
npm run data:scan    # 距離・minPts ごとの結果と計算時間を表示
```

```bash
npm run dev
```

```bash
npm test && npm run build   # 検証とビルド（dist/ に出力）
```

公開先：https://shinyanakashima.github.io/30daymapchallenge-2026day4-clusters/

SNS 共有用のプレビュー画像 `public/og.png` は `node scripts/make-og.cjs`（ビルド後に `npx vite preview --port 4173` を起動した状態で実行）で作り直せる。

`main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）がテスト・ビルドし、`dist/` を GitHub Pages へデプロイする（Pages の公開元は「GitHub Actions」）。

### 構成

- Vite 7.3.7 ＋ React 19.2.9 ＋ TypeScript 5.9.3 ＋ MapLibre GL JS 5.24.0（依存バージョンは固定）
- 背景地図：Sentinel-2 cloudless と地理院タイル（衛星写真）、Terrain Tiles（夜の地形）、地理院ベクトルタイル（海岸線・道路・地名）。配色は `src/mapStyle.ts`
- `src/components/Overlay.tsx`：地図の上に重ねる UI（札・操作バー・窓・ガイド）
- `src/lib/`：距離・DBSCAN・配色の計算モジュール、`src/blob.ts`：にじみの寸法
- `tests/`：計算（距離境界・孤立点・同位置点・連鎖・minPts・カテゴリ変更後の再計算・再現性・色の引き継ぎ）、URL、配信データ件数の検証
